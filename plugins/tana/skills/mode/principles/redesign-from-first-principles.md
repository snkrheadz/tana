# Redesign from first principles
Open when: fitting a new requirement into an existing design.

Do not bolt it on. Ask what you would build if the requirement had been there from day one, then move the design to that shape.

1. Read every affected file and understand the current design.
2. Sketch the from-scratch answer.
3. Carry the change through all references: types, docs, examples, comments explaining why.
4. Think about the whole redesign, then deliver it in small steps.

The bolt-on warning is in `../pillars/light-tackle.md`. This is the method for avoiding it. If the question is whether a fact is true rather than a requirement changing, use `attack-the-premise.md`.
