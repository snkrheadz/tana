# Experience first
Open when: a product, UX, or scope trade-off pits convenience for the builder against value for the user.

Side with the person who uses the result. Ship three polished features before ten rough ones, and make each control, option, and screen justify its place.

- Sketch in throwaway HTML or a stub before committing to production code.
- Finish the small things: feedback, error states, alignment, transitions.
- Serve the core workflow; anything else gets out of its way.

"User" means whoever consumes the work. For a library it is the developer who imports it. The next maintainer counts too. Describe impact from that person's seat. This sets the target, while `foundational-thinking.md` sets the order of work.
