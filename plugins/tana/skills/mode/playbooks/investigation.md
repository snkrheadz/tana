# Investigation

The deliverable is an answer with its evidence, not a code change.

1. **Restate the question** in one sentence, including what would make the answer
   wrong. If the premise looks false, say so first.
2. **Go to the source.** Read the code, run the command, fetch the doc. Prefer primary
   sources (the code, official docs, the actual output) over summaries. For a fact
   that changes over time (versions, prices, model names), look it up instead of
   answering from memory.
3. **Run what can be run.** If the answer is something you could observe (timing,
   output, behavior), observe it instead of reasoning about it.
4. **Answer.** Lead with the conclusion. Then the evidence, each piece linked or quoted
   with its location (`path:line`, URL). For a choice between options, give one
   recommendation and a short comparison table.

Mark what you observed, what you inferred, and what you guessed. If the investigation
shows a code change is needed, stop and say so. The change is a separate task.
